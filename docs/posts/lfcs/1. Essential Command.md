# Essential Command
## 1. Log to Local and Remote Graphical and Text mode console
- Trong Linux, chúng ta thường nghe đến các khái niệm: Console, Virtual Terminal hay Terminal Emulator. Vậy chúng là gì? Với Linux hiện đại, console ám chỉ màn hình nơi mà hệ điều hành hiển thị văn bản và cho phép người dùng login và thực hiện câu lệnh. Terminal Emulator là một ứng dụng giao diện (GUI) thực hiện hành vi như console. Virtual Terminal là ...
- Lịch sử: Ngày xưa khi máy tính đắt đỏ, một trường đại học hoặc một tổ chức chỉ có một máy tính. Nhưng nhiều người muốn kết nối và thao tác với nó, họ dùng thiết bị vật lý để gõ câu lệnh và hiển thị lên màn hình những gì đang diễn ra. Thiết bị này gọi là `console` hoặc `terminal`. Vì vậy, thay vì setup rất nhiều máy thì chỉ cần 1 máy tính và mọi người kết nối tới nó thông qua terminal. 
- Ví dụ: Khi máy tính booting, màn hình hiển thị những text, nó phản ánh những gì đang xảy ra.
- Khi một Linux server được cài đặt, nó thường không đi kèm giao diện người dùng (GUI). Để kết nối đến một Linux server thường thông qua SSH Protocol hoặc telnet. Trước đây chúng ta thường dùng telnet tuy nhiên nó không được bảo mật vì không được mã hóa đường truyền. SSH thì được mã hóa và an toàn hơn rất nhiều. 
- Trên Linux Server sẽ chạy SSH daemon nó sẽ chấp nhận các kết nối. Ở client thì chúng ta cần chạy SSH Client, khi đó nó sẽ yêu cầu kết nối đến Server thông qua SSH
```
ssh quanghuy@192.168.0.1
```
Thông thường, Linux Server thường được cài OpenSSH Client sẵn.

## 4. Create and Manage Hard Links
- Hard link: Giả sử chung ta có 2 user jane và quanghuy trong cùng 1 máy tính. quanghuy có file ảnh trong thư mục picture của quanghuy.
```
$ echo "Picture of Milo the dog" > ~/family_dog.jpg
$ stat ~/family_dog.jpg
  File: family_dog.jpg
  Size: 24              Blocks: 8          IO Block: 4096   regular file
Device: 820h/2080d      Inode: 1926        Links: 1
Access: (0644/-rw-r--r--)  Uid: ( 1000/quanghuy)   Gid: ( 1000/quanghuy)
Access: 2026-05-11 21:36:02.974115168 +0700
Modify: 2026-05-11 21:36:02.974115168 +0700
Change: 2026-05-11 21:36:02.974115168 +0700
 Birth: 2026-05-11 21:36:02.974115168 +0700
```
- Các file system như ZFS, ext4 và một số loại khác lưu trữ data trên inodes. Data được lưu phân tán trên ổ cứng, Inode biết chính xác data đó nằm ở chỗ nào trên ổ, nó cũng lưu thông tin metadata như permissions, last modified, last access... File sẽ trỏ vào Inode và Inode trỏ vào các block data.
- Trường Link hiển thị `Links: 1` hiển thị số lượng hard link đến Inode.
- Nhưng tại sao lại cần hard link? Giả sử quanghuy muốn share ảnh cho Jane anh ta có thể copy các ảnh này cho Home của Jane
```
cp -r /home/quanghuy/*.jpg /home/jane/
```
- Nhưng vấn đề xảy ra ở đây, nếu số lượng ảnh quá lớn việc copy vừa gây mất thời gian vừa tốn bộ nhớ gấp đôi cho cùng 1 ảnh. Thay vì đó, chúng ta có thể tạo hard link cho jane
```
$ ln path_to_target_file path_to_link_file
$ ln /home/quanghuy/family_dog.jpg /home/jane/family_dog.jpg
```
- Khi đó, các file trong Jane home sẽ trở tới các Inode của các ảnh đã lưu trên disk thay vì tạo ra data khác.
```
$ stat family_dog.jpg
  File: family_dog.jpg
  Size: 24              Blocks: 8          IO Block: 4096   regular file
Device: 820h/2080d      Inode: 1926        Links: 2
Access: (0644/-rw-r--r--)  Uid: ( 1000/quanghuy)   Gid: ( 1000/quanghuy)
Access: 2026-05-11 21:36:02.974115168 +0700
Modify: 2026-05-11 21:36:02.974115168 +0700
Change: 2026-05-11 21:36:02.974115168 +0700
 Birth: 2026-05-11 21:36:02.974115168 +0700
```
- Khi một người muốn xóa file khỏi thư mục, họ chỉ cần xóa hard link. Chi khi số lượng Link của Inode là 0, data sẽ tự động được dọn dẹp.
- Nhược điểm của hard link:
    - Chỉ có thể hard link được file, không phải directory
    - Chỉ có thể hard link trên cùng file system

- Lưu ý: Khi tạo hard link cần chú ý tạo đúng và đủ quyền đề người khác có thể đọc được
```
$ useradd -a -G family quanghuy
$ useradd -a -G family jane
$ chmod 660 /home/quanghuy/family_dog.jpg
```

# 5. Create and Manage Soft Link
- Nếu như hard link point to Inode thì soft link là file point vào path. Ví dụ chúng ta có file family_dog.jpg, chúng ta tạo soft link trỏ vào đường dẫn tới file family_dog.jpg đó.
- Tạo soft link
```
# ln -s path_to_target_file path_to_link_file
$ ln -s /home/quanghuy/family_dog.jpg family_dog_shortcut.jpg
$ ls -l
lrwxrwxrwx  1 quanghuy quanghuy       14 May 11 21:53  family_dog_shortcut.jpg -> family_dog.jpg
$ readlink family_dog_shortcut.jpg
family_dog.jpg
```
- Soft link có thể dùng với file và directory
- Soft link có thể dùng với các file trên các filesystem khác nhau

## 6. List, Set and Change standard File Permission
- trong Linux, mỗi file, directory đều được set quyền nhất định. Chúng ta có thể xem được quyền của các file và directory thông qua ls.
```
$ ls -l
-rw-r--r--  1 quanghuy family         24 May 11 21:36  family_dog.jpg
```
- Trong đó:
    - `-rw-r--r--` là quyền truy cập của file
    - `quanghuy` là owner
    - `family` là group
    - `24 May 11 21:36` là thời gian tạo

- Thay đổi group của file
```
$ sudo chgrp group_name file/directory
$ sudo chgrp family family_dog.jpg
$ sudo chgrp sudo family_dog.jpg
```

- Hiển thị danh sách groups của user hiện tại
```
groups
```

- Thay đổi owner của file/directory
```
$ sudo chown jane family_dog.jpg
```

- Bảng hiển thị loại file

| File Type | Identifier |
| --------- | ---------- |
| Directory |     d      |
| Regular File | - |
| Character Device | c |
| Link | l |
| Socket file | s |
| Pipe | p |
| Block device | b |

- Permission
```
             r w x | r w x | r w x 
              owner  group   other
```
- bảng Mô tả

| Bit | Purpose | Description |
|---- | ------- | ----------- |
| r | Read Directory | Đối với directory: User được xem danh sách file (ls) |
| w | Write to Directory | Đối với directory: User có thể đổi tên file trong đó | 
| x | Execute Into | Đối với directory: user có thể cd vào file |
| - | No Permission | | 

- Evaluating Permissions
- Giả sử chúng ta có file như sau
```
$ ls -l family_dog.jpg
-r--rw---- 1 quanghuy family 24 May 11 21:36 family_dog.jpg
```
- Chúng ta là owner có quyền read, chúng ta ở trong group family có read write. Thử ghi thêm vào file
```
$ echo "Add this line to bottom of the file" >> family_dog.jpg
zsh: permission denied: family_dog.jpg
```
- Lý do bị permission denied là do quyền được đánh giá từ trái qua phải. owner -> group -> other. Khi người dùng thao tác với file, linux sẽ kiểm tra lần lượt xem người dùng này ở nhóm quyền nào từ trái qua. Như ví dụ người dùng này là owner thì có quyền đọc nhưng không có quyền ghi nên khi thực hiện sửa file sẽ bị permission denied. Nếu thực hiện bằng user khác trong group `family` thì ok.

- Adding Permission
```
$ chmod permissions file/directory
$ chmod u+w family_dog.jpg # Thêm quyền write cho user quanghuy
```
- Bảng permission
- Thêm permission
| - | Option | Examples |
| - | - | - |
| user | u+ | u+w / u+rw / u+rwx |
| group | g+ | g+w / g+rw / g+rwx |
| others | o+ | o+w / o+rw / o+rwx |

- Xóa permission
| - | Option | Examples |
| - | - | - |
| user | u- | u-w / u-rw / u-rwx |
| group | g- | g-w / g-rw / g-rwx |
| others | o- | o-w / o-rw / o-rwx |
```
chmod o-r family_dog.jpg # Xóa quyền đọc của group family
```

- Chỉ định đúng permission: Tức là chỉ định quyền cho user/group/other
| - | Option | Examples |
| - | - | - |
| user | u= | u=w / u=rw / u=rwx |
| group | g= | g=w / g=rw / g=rwx |
| others | o= | o=w / o=rw / o=rwx |
```
$ chmod g=r family_dog.jpg # Chỉ cho group family đọc
$ chmod g= family_dog.jpg # Xóa toàn bộ quyền
```

- Chaining Permission
```
chmod u+rw,g=r,o= family_dog.jpg # Owner được đọc ghi, group được dọc và other không được quyền gì
```
- Octal Permissions
- Mỗi nhóm quyền được hiển thị binary 01 hoặc cũng có thể biểu diễn dưới dạng octal (cơ số 8).

| Binary | Octal |
| ------ | ----- |
| 000 | 0 |
| 001 | 1 |
| 010 | 2 |
| 011 | 3 |
| 100 | 4 |
| 101 | 5 |
| 110 | 6 |
| 111 | 7 |

- Hoặc cũng có thể tính dễ dàng thông qua 
```
        r w x | r w x | r w x
        4 2 1 | 4 2 1 | 4 2 1
          7       7       7 

        r w - | r - - | r - -
        4 2 0 | 4 0 0 | 4 0 0
          6       4       4
```
```
chmod 644 family_dog.jpg
```
